# План работ

Подход: не писать эмуляцию SA-1110 с нуля (она уже есть в QEMU как
`hw/arm/strongarm.c`), а написать board-файл для Jornada 720 по образцу
`hw/arm/collie.c`, постепенно добавляя периферию.

## 1. Минимальный скелет машины

Цель: `qemu-system-arm -M jornada720 -bios <rom>` хотя бы не падает сразу
и что-то видно в serial-консоли (UART).

- [x] Завести `hw/arm/jornada720.c`: создание CPU (SA1110-совместимое ARM-ядро),
  инициализация strongarm-чипа через существующий helper из strongarm.c
  (как это делает `collie.c`).
  Готово: исходник лежит в `src/hw/arm/jornada720.c` (наш репозиторий,
  версионируется), в `qemu-src/hw/arm/jornada720.c` — симлинк на него.
  Зарегистрирован через `qemu-src/hw/arm/Kconfig` (`config JORNADA720`,
  по образцу COLLIE) и `qemu-src/hw/arm/meson.build`
  (`CONFIG_JORNADA720` → `jornada720.c`) — эти два файла правятся прямо
  в рабочей копии `qemu-src` и не коммитятся (она вне git нашего репо),
  так что при переклонировании `qemu-src` их нужно будет внести заново.
  RAM (32 MiB на `SA_SDCS0`) и флеш (32 MiB на `SA_CS0`, через
  `pflash_cfi01_register`, без вызова `arm_load_kernel` — грузим не
  Linux zImage, а ROM с собственным загрузчиком CE) подключены.
  Проверено: `qemu-system-arm -M help` показывает `jornada720`,
  `-M jornada720 -nographic` стартует и не падает даже без ROM-образа.
- [x] Замаппить реальный ROM-образ и посмотреть, что происходит.
  Результат: serial-консоль молчит — не потому что не подключена, а
  потому что boot-код зависает раньше, чем доходит до инициализации UART.
  Подробный разбор (с фиксом CP15-регистра, из-за которого раньше падало
  ещё в первых 30 инструкциях) — в `docs/research.md`, раздел "Прогон
  реального ROM". Текущая точка зависания: бесконечный poll на
  SA-1111 (`0x40000810`).
- [x] Критерий готовности **скорректирован дважды**: сначала выяснилось,
  что до UART ещё далеко (сначала SA-1111), потом — что после SA-1111
  идёт ещё и Epson-контроллер дисплея. UART по-прежнему молчит, но это
  уже не текущий приоритет — см. 1.5 и 1.6.

## 1.5. SA-1111 — минимально достаточная модель ✅ (частично)

- [x] Точные базы блоков SA-1111 добыты не из даташита (bitsavers-копия
  битая), а из реальных исходников Linux (`arch/arm/include/asm/hardware/
  sa1111.h` + `arch/arm/common/sa1111.c`, через jsdelivr — GitHub напрямую
  заблокирован сетью телефона). SSP-база оказалась `0x0800` (не угадывалась
  из упрощённого заголовка), PCMCIA — `0x1800`. Подробности и то, как
  опровергли гипотезу "это USB" — в `docs/research.md`.
- [x] Реализован узкий `MemoryRegion` с кастомными `ops` поверх SSP-диапазона
  (`0x40000800`, 4 КиБ), возвращающий фиксированные "статус"-биты по
  аналогии с on-chip `strongarm_ssp` (`TNF|RNE|TFS|RFS`, без "busy"/"overrun").
  **Экспериментально, не подтверждено по настоящему даташиту SA-1111**
  (глава 8, Table 8-8 — так и не достали читаемую копию).
- [x] Критерий готовности выполнен: poll на `0x810` больше не висит,
  код идёт дальше — прямиком в инициализацию Epson-контроллера (см. 1.6).
- [ ] Осталось при желании: найти рабочую копию даташита SA-1111 (глава 8)
  и заменить догадку про биты SSP на подтверждённые значения — на случай
  если где-то дальше эта же заглушка всё-таки даст сбой на другом бите.

## 1.6. Epson-контроллер дисплея — новый стопор

После SA-1111 код полностью обнуляет весь Epson framebuffer (все 512 КиБ)
и пишет `0x01` в регистр `0x1fc` (1 байт) — и виснет сразу после этого,
детерминированно, на том же месте при повторных запусках. Serial-консоль
всё ещё молчит.

- [ ] Определить точную модель Epson-чипа на Jornada 720 (в TOC самого
  SA-1111 даташита он вообще не упоминается — это отдельный вендорский чип
  за пределами SA-1110/SA-1111; кандидаты — семейство Epson SED13xx).
- [ ] Понять семантику регистра `0x1fc` и то, какой статус-бит код ждёт
  после записи в него (тот же паттерн "конфиг → poll готовности", что и
  с SSP).
- [ ] У QEMU нет вообще ни одной реализации ни для одной модели Epson
  SED13xx — придётся либо искать даташит конкретной модели, либо
  реализовывать по аналогии/догадке, как это уже сработало с SSP.
- [ ] Критерий готовности: poll после записи `0x1fc` завершается, код
  идёт дальше (в идеале — наконец добирается до UART, это по-прежнему
  финальная цель шага 1).

## 2. Экран

**Пересмотрено после разбора strongarm.c (см. docs/research.md):**
LCD-контроллера SA-1110 в QEMU **нет вообще** (ни в strongarm.c, ни в
collie.c). Это не мелкая доработка "передать конфиг панели", а отдельное
устройство, которое нужно писать с нуля — по сути ещё один шаг размером
с 1.

  экран там реализован, это готовый референс логики).

  тайминги, формат пикселей).
