# План работ

Подход: не писать эмуляцию SA-1110 с нуля (она уже есть в QEMU как
`hw/arm/strongarm.c`), а написать board-файл для Jornada 720 по образцу
`hw/arm/collie.c`, постепенно добавляя периферию.

## 0. Подготовка окружения

- [x] Склонировать исходники QEMU, собрать `qemu-system-arm` из исходников
  локально (понадобится для итерации на machine-файле — apt/apk-пакет
  тут не подойдёт, т.к. будем менять код).
  Готово: `qemu-src/` (shallow clone), собрано в `build/` (`--target-list=arm-softmmu`),
  бинарник `build/qemu-system-arm` v11.1.50, `-M collie` доступна.
- [ ] Прочитать и законспектировать `hw/arm/collie.c` + `hw/arm/strongarm.c`/
  `strongarm.h` — что конкретно предоставляет strongarm.c "из коробки"
  (UART, GPIO, timers, RTC, PCMCIA, DMA, LCD controller), а что machine-файл
  должен доопределить сам (memory map, флеш, кнопки, панель).
- [ ] Достать ROM-дамп Jornada 720 (вне репозитория, локально у пользователя).
- [ ] Достать/свести карту памяти платы (jornada720.txt + сверка с MAME
  `jornada.cpp`, если исходники доступны для чтения).

## 1. Минимальный скелет машины

Цель: `qemu-system-arm -M jornada720 -bios <rom>` хотя бы не падает сразу
и что-то видно в serial-консоли (UART).

- [x] Завести `hw/arm/jornada720.c`: создание CPU (SA1110-совместимое ARM-ядро),
  инициализация strongarm-чипа через существующий helper из strongarm.c
  (как это делает `collie.c`).
  Готово: исходник лежит в `src/hw/arm/jornada720.c` (наш репозиторий,
  версионируется), в `qemu-src/hw/arm/jornada720.c` — симлинк на него.
  Зарегистрирован через `qemu-src/hw/arm/Kconfig` (`config JORNADA720`,
  по образцу COLLIE) и `qemu-src/hw/arm/meson.build`
  (`CONFIG_JORNADA720` → `jornada720.c`) — эти два файла правятся прямо
  в рабочей копии `qemu-src` и не коммитятся (она вне git нашего репо),
  так что при переклонировании `qemu-src` их нужно будет внести заново.
  RAM (32 MiB на `SA_SDCS0`) и флеш (32 MiB на `SA_CS0`, через
  `pflash_cfi01_register`, без вызова `arm_load_kernel` — грузим не
  Linux zImage, а ROM с собственным загрузчиком CE) подключены.
  Проверено: `qemu-system-arm -M help` показывает `jornada720`,
  `-M jornada720 -nographic` стартует и не падает даже без ROM-образа.
- [ ] Замаппить туда реальный ROM-образ (когда он будет) и посмотреть
  вывод в serial-консоли (UART уже подключен через `sa1110_init`,
  дополнительно ничего делать не нужно — просто указать `-drive
  if=pflash,file=<rom>` и `-nographic`/`-serial stdio`).
- [ ] Критерий готовности: в консоли видно хоть какой-то вывод загрузчика
  (даже если потом падает на инициализации SA-1111/экрана/др. периферии).

## 2. Экран

**Пересмотрено после разбора strongarm.c (см. docs/research.md):**
LCD-контроллера SA-1110 в QEMU **нет вообще** (ни в strongarm.c, ни в
collie.c). Это не мелкая доработка "передать конфиг панели", а отдельное
устройство, которое нужно писать с нуля — по сути ещё один шаг размером
с 1.

- [ ] Изучить LCD-контроллер SA-1110 по даташиту (регистры DBAR/LCCR0-3 и т.п.)
  и/или по реализации в MAME (`sa1110.cpp`, раз там UI уже виден — значит
  экран там реализован, это готовый референс логики).
- [ ] Написать новое устройство (например `hw/display/strongarm_lcd.c` в
  нашем форке) с минимальной поддержкой панели Jornada 720 (разрешение,
  тайминги, формат пикселей).
- [ ] Подключить его в `jornada720.c` по адресу LCD-контроллера SA-1110.
- [ ] Критерий готовности: во framebuffer-окне QEMU виден лого/экран загрузки
  Windows CE (даже без ввода).

## 3. Ввод: клавиатура и тачскрин

- [ ] Разобрать, как в реальной Jornada 720 устроена клавиатурная матрица
  и тачскрин (ADC-контроллер) — по документации и/или по MAME jornada.cpp,
  где это уже реализовано.
- [ ] Реализовать эквивалент в QEMU machine-файле.
- [ ] Критерий готовности: можно кликать/вводить текст и CE реагирует.

## 4. Второстепенная периферия (по необходимости)

- [ ] IrDA, звук, подсветка, батарея/питание — по мере того, что реально
  требуется для стабильной работы CE (не факт, что всё это нужно сразу).

## 5. Стабилизация и (опционально) апстрим

- [ ] Сверить поведение с MAME-версией как с эталоном (что у них "не работает
  до конца" — не пытаться переизобретать те же грабли).
- [ ] Прогнать на постмаркет-девайсе (Pixel 3a XL) — учесть, что TCG-эмуляция
  SA-1110 на мобильном SoC может быть медленнее, чем на десктопе (MAME на
  i5-4670K уже "очень медленный", так что ожидания по производительности
  нужно держать сдержанными).
- [ ] Если результат стабильный — рассмотреть отправку патча в апстрим QEMU
  (потребует соблюдения их code style / review-процесса).

## Явно не в скоупе (пока)

- Поддержка других моделей Jornada (56x/SA-1110 линейка, 6xx/7xx SH3-линейка).
- Полная точность эмуляции (звук, IrDA) — приоритет: загрузиться и быть
  минимально управляемой.
